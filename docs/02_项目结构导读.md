## 1. 全景图：项目分了哪几层？

整个项目是一个**分层的洋葱**——每层只跟相邻层打交道，层与层之间通过「接口」约定好长相，不关心对方内部怎么实现。

```
┌──────────────────────────────────────────────────────────┐
│                        入口层 (CLI)                        │
│              src/cli.py —— 你敲键盘看到的终端界面           │
│       职责：循环读你的输入，把回复逐字打印出来               │
└─────────────────────────┬────────────────────────────────┘
                          │ 你输入的一句话（字符串）
                          ▼
┌──────────────────────────────────────────────────────────┐
│                      Agent 核心                           │
│          src/core/agent.py —— ChatAgent                   │
│       职责：把字符串包装成「消息」，交给底层模型，          │
│              并把模型吐回来的文字一段段地传回去             │
└─────────────────────────┬────────────────────────────────┘
                          │ 一组消息 list[Message]
                          ▼
┌──────────────────────────────────────────────────────────┐
│                 Provider 抽象层（LLM 适配）                │
│    src/core/provider.py —— BaseProvider（接口/契约）       │
│    src/providers/sensenova.py —— SenseNovaProvider        │
│       职责：真正跟「商汤日日新」服务器说话，                │
│              一个接口管「换任何模型都不改上层代码」         │
└─────────────────────────┬────────────────────────────────┘
                          │ HTTPS + OpenAI 协议
                          ▼
┌──────────────────────────────────────────────────────────┐
│                  商汤日日新大模型服务                       │
│            https://token.sensenova.cn/v1                   │
└──────────────────────────────────────────────────────────┘
```

**一句话记住分层**：**界面(cli) 问 大脑(agent)，大脑 找 翻译(provider)，翻译 请 模型(商汤) 回答**。

两边的配角：

```
┌──────────────────────────────────────────────┐
│    src/config.py   配置中心                     │
│    从 .env 读 base_url / api_key / model       │
│    → 所有层需要参数时都找它要                  │
│                                               │
│    src/core/models.py  消息模型                │
│    Message(role, content) —— 统一的数据格式     │
│    → 所有层之间传话都用这个格式                │
│                                               │
│    src/core/utils.py  小工具                   │
│    scrub_text() —— 清理坏字符，防崩溃          │
└──────────────────────────────────────────────┘
```

> 为什么 cli 不直接调 provider？因为中间夹着 agent 这一层。将来要加"工具调用 / RAG / 记忆"时，都是往 agent 里加逻辑，cli 和 provider 都不用动。这就是**为后续扩展留位**。

## 2. 运行时流程：你敲"你好"之后发生了什么？

这是一次对话从输入到显示的完整时间线（时序图）：

```
 你          cli.py              agent.py            sensenova.py          商汤服务器
 │             │                    │                    │                  │
 │ 敲入"你好"   │                    │                    │                  │
 ├────────────▶│                    │                    │                  │
 │             │ print 提示         │                    │                  │
 │◀────────────┤                    │                    │                  │
 │             │ agent.respond("你好")                   │                  │
 │             ├───────────────────▶│                    │                  │
 │             │                    │ scrub_text 清洗输入  │                  │
 │             │                    │ 包装成 Message      │                  │
 │             │                    │ chat_stream(消息们) │                  │
 │             │                    ├───────────────────▶│                  │
 │             │                    │                    │ 发起流式HTTP请求    │
 │             │                    │                    ├─────────────────▶│
 │             │                    │                    │                  │
 │             │                    │   每来一小段就传回   │  服务器一段段吐出    │
 │             │◀───────────────────│◀──────────────────│◀─────────────────│
 │             │ for 循环 + flush    │                    │                  │
 │ 逐字看到回复  │◀───────────────────┤                    │                  │
 │             │                    │                    │                  │
```

**流式（streaming）是怎么回事？**

普通请求像收快递：等整箱到了你才看见。流式请求像接水管：**水是一滴滴流过来的，来一滴你就看到一滴**。

代码上靠 Python 的**生成器（`yield`）**实现——`chat_stream` 每收到模型吐的一小段文字就 `yield` 出去，cli 端每收到一段就 `print(..., flush=True)` 立即刷新屏幕：

```python
# cli.py 里：一段一段打印，flush=True 保证立即显示
for chunk in agent.respond(text):
    print(chunk, end="", flush=True)
```

```python
# sensenova.py 里：模型吐一段，就转交一段
def chat_stream(self, messages):
    stream = self._client.chat.completions.create(..., stream=True)
    for chunk in stream:                     # 每个 chunk = 模型吐的一小段
        if chunk.choices and chunk.choices[0].delta.content:
            yield scrub_text(chunk.choices[0].delta.content)   # 转交出去
```

> ⚠️ **实测发现（重要）**：商汤 `sensenova-6.8-flash-lite` 服务端**会先把整个回复算完，再一次把所有分片推给客户端**。实测长问题时静默等待 75 秒，然后 16 个分片在 0.25 秒内全部到达。所以无论问题长短，表现都是"先等待，然后整段瞬间出现"——**这是服务端行为，不是代码 bug**。我们的代码已经做到位（`stream=True` + 逐块刷新）。因此 CLI 加了一个"思考中…"提示，避免等待时一片空白。若日后要"逐字打字机"效果，需要换一个支持真流式的模型/服务商。

## 3. 逐个模块讲解

### 3.1 `src/config.py` —— 配置中心

从 `.env` 文件读配置，用 `pydantic-settings` 自动映射成 Python 对象。

```python
class Settings(BaseSettings):
    sensenova_base_url: str = "https://token.sensenova.cn/v1"
    sensenova_api_key: str = ""
    sensenova_model: str = "sensenova-6.8-flash-lite"
    max_tokens: int | None = None
    temperature: float | None = None

settings = Settings()   # 模块级单例：全项目就这一份
```

- **职责**：所有配置集中一处，改模型/换地址只动 `.env`，不用改代码。
- **被谁用**：`cli.py` 构建 Agent 时取参数；`sensenova.py` 需要 key/模型名。

### 3.2 `src/core/models.py` —— 消息模型（数据格式）

整个项目**层与层之间传话用的统一格式**，采用 OpenAI 消息协议。

```python
class Role(str, Enum):
    SYSTEM = "system"      # 系统（设定角色/规则）
    USER = "user"          # 用户（你）
    ASSISTANT = "assistant" # 助手（模型）

@dataclass
class Message:
    role: Role
    content: str

    def to_openai_dict(self) -> dict:
        # 转成 OpenAI 协议要求的字典 {"role": ..., "content": ...}
        return {"role": self.role.value, "content": self.content}

@dataclass
class Conversation:
    messages: list[Message]   # 多轮对话历史（M2 记忆系统用）
```

- **职责**：定义「消息长什么样」。
- **为什么用它**：等将来要传图片（多模态）、传工具调用结果时，直接在这个结构上加字段，所有层都跟着升级，不用推倒重来。
- **谁在用**：agent 造消息 → provider 转成 dict → 发给商汤。

### 3.3 `src/core/provider.py` —— 接口（契约）

这里只有**抽象接口**，没有实现——它规定"任何一个模型接入商都要长这样"：

```python
class BaseProvider(ABC):
    @abstractmethod
    def chat(self, messages: list[Message]) -> str:
        """非流式：一口气返回完整回复"""

    @abstractmethod
    def chat_stream(self, messages: list[Message]) -> Iterator[str]:
        """流式：一段一段地返回回复"""
```

- **职责**：画出一条"模型接入标准"。
- **为什么重要**：今天用的是商汤，明天想换成 DeepSeek / 千问 / 豆包，只要再写一个 `XxxProvider(BaseProvider)` 类实现这两个方法，**Agent 核心一行都不用改**。后续"多路并发"也靠这层挂多个 provider。
- **谁实现它**：`sensenova.py`。

### 3.4 `src/providers/sensenova.py` —— 商汤实现

真正跟商汤服务器说话的人。基于 `openai` SDK，只需换 `base_url` 和 `api_key`：

```python
from openai import OpenAI

class SenseNovaProvider(BaseProvider):
    def __init__(self, base_url, api_key, model, ...):
        self._client = OpenAI(base_url=base_url, api_key=api_key)
        ...

    def chat(self, messages):          # 非流式（兜底用）
        resp = self._client.chat.completions.create(model=..., messages=..., stream=False)
        return resp.choices[0].message.content or ""

    def chat_stream(self, messages):   # 流式（主用）
        stream = self._client.chat.completions.create(model=..., messages=..., stream=True)
        for chunk in stream:
            if chunk.choices and chunk.choices[0].delta.content:
                yield scrub_text(chunk.choices[0].delta.content)
```

**它还多做了一件事：健壮性**（`_is_retryable` 判断哪些错误可以重试）：

| 情况 | 处理 |
|---|---|
| 限流 429 / 断网 / 服务端 5xx | **自动重试**，指数退避（等 2s→4s→8s） |
| 鉴权失败 4xx | 不重试，直接报错 |
| 流式中途编码异常 | 回退非流式一次，保证对话不中断 |

### 3.5 `src/core/agent.py` —— Agent 核心

MVP 阶段它是个"直答中转站"：把字符串包装成消息，丢给 provider，再把回复一段段转交出去。

```python
class ChatAgent:
    def __init__(self, provider: BaseProvider):  # 传入任意符合接口的 provider
        self._provider = provider

    def respond(self, message: str) -> Iterator[str]:
        # 1) 清洗输入（防 Windows 编码坏字符）
        # 2) 包装成 USER 消息
        # 3) 交给 provider 流式返回
        messages = [Message(role=Role.USER, content=scrub_text(message))]
        yield from self._provider.chat_stream(messages)
```

- **职责**：业务逻辑的"家"。现在只是直答；**将来加记忆、工具调用、RAG 都往这里加**，接口 `respond()` 不变，上层不用改。
- **依赖注入**：agent 不自己 new 一个 provider，而是外部传进来（`cli.py` 传的）。好处是测试时能传入一个"假 provider"（mock），不用真花钱调模型。

### 3.6 `src/core/utils.py` —— 小工具

`scrub_text()` 处理 Windows 编码历史问题的残留坏字符：

```python
def scrub_text(text: str) -> str:
    # 把孤立代理项还原成正常字符（如 emoji）；还原不了就替换为 �，保证不崩溃
    return text.encode("utf-8", "surrogateescape").decode("utf-8", "replace")
```

### 3.7 `src/cli.py` —— 入口

```python
def build_agent() -> ChatAgent:
    # 检查 API Key → 用配置构造 SenseNovaProvider → 包一层 ChatAgent
    return ChatAgent(provider)

def main():
    _enable_utf8_stdio()      # Windows 编码统一 UTF-8
    agent = build_agent()
    while True:
        text = input("你：").strip()
        if text == "/exit":  break
        if text == "/help":  print(HELP_TEXT); continue
        print("AI：", end="", flush=True)
        for chunk in agent.respond(text):
            print(chunk, end="", flush=True)   # 流式逐字输出
        print()
```

- **职责**：面向用户的一层。构建 Agent → 循环读输入 → 处理命令 → 流式打印。
- **刻意设计**：cli 只依赖 `agent.respond()` 这一个入口。将来加 Web 界面时，同样调用这个入口，包一层 HTTP 就行——**UI 随便换，核心不动**。

## 4. 模块依赖关系（谁引用谁）

```
        src/cli.py（入口）
           │
           ├─▶ src/config.py（拿配置）
           │
           ├─▶ src/core/agent.py（ChatAgent）
           │      ├─▶ src/core/provider.py（BaseProvider 接口）
           │      ├─▶ src/providers/sensenova.py（实现接口）◀─┐
           │      ├─▶ src/core/models.py（Message）            │
           │      └─▶ src/core/utils.py（scrub_text）          │
           └─▶ src/core/models.py（Message）                   │
                                                               │
        依赖方向：上层依赖下层，下层不依赖上层                   │
        商汤服务 ←─ 只有 sensenova.py 会真的联网 ───────────────┘
```

**记住一条铁律**：箭头都是**从上往下**（上层依赖下层），没有从下往上的。这就是"分层架构"的规矩——底层（provider/models）不知道也不关心顶层（cli）是谁。

## 6. 为后续扩展预留了什么？

| 后续里程碑 | 预留位置 | 届时怎么改 |
|---|---|---|
| M2 记忆系统（多轮上下文） | `agent.respond()` 参数 | 从"单条消息"改为"整个会话历史"传入 |
| M3 工具调用 / ReAct | `agent.py` | 直答实现换成"循环执行"实现，接口不变 |
| M4 RAG | 记忆层 | 给 agent 接向量检索 |
| M5 MCP | agent + provider | 工具标准化接入执行循环 |
| M6 多模态 | `models.py` 消息结构 | `content` 扩展为文本+图片列表 |
| 换模型 / 多路并发 | `provider.py` | 再写一个 `XxxProvider` 即可，Agent 零改动 |
| Web 界面 | `cli.py` 这一层 | 新增 `api/` 层复用同一 Agent，cli 可留可弃 |
