# 18 用户体系设计（M10）

> **目标**：在现有 Docker + Tailscale 封闭 Beta 上补齐应用层身份、邀请注册和会话隔离。Tailscale 继续负责网络入口；本期不把服务开放到公网，不接邮箱、短信或第三方 OAuth。

## 1. 为什么仍然需要账号

Tailscale 能确认“哪台已加入 Tailnet 的设备”访问了服务，但 Agent 目前所有会话都在同一 `data/sessions/` 下，不能确认“哪个用户拥有哪份对话”。一旦邀请测试者，他们会看到并能操作彼此的会话。

M10 的安全边界为：**网络层先经过 Tailscale，应用层再经过登录，数据层最后校验会话归属**。前端隐藏列表不是权限控制；每个会话 API 都必须在服务端校验当前登录用户。

## 2. 首版范围

- 用户名 + 密码注册、登录、退出、查看当前身份；不存储明文密码。
- 注册须提供服务器 `.env` 中的邀请口令；口令不下发到浏览器、不写日志。
- 登录态使用随机、可撤销、带过期时间的 `HttpOnly` Cookie；浏览器 JavaScript 无法读取 token。
- 会话只能由其所有者列出、读取、发送、清空和删除。
- 首次启用时，已有 JSON 会话归属给第一个完成注册的管理员，避免历史数据丢失或意外暴露。

本期不做：找回密码、修改密码、邮箱验证、多人管理员、邀请码管理后台、公开注册和跨设备实时同步。

## 3. 数据归属与存储

新增 `data/auth.db`（SQLite，与 `data/sessions/` 一同挂载进 Docker），由 `AuthStore` 独占访问：

| 表 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| `users` | `id`, `username`, `password_hash`, `password_salt` | 用户名唯一；密码用 `hashlib.scrypt` 派生，绝不保存明文 |
| `login_sessions` | `token_hash`, `user_id`, `expires_at` | 仅保存 token 的 SHA-256 摘要；退出时删除，过期后拒绝 |
| `session_owners` | `agent_session_id`, `user_id` | `agent_session_id` 唯一，防止一个会话被多个用户拥有 |

SQLite 写操作在短事务中完成；用户创建依赖数据库唯一约束避免并发重名。JSON 对话仍由 `MemoryStore` 负责，`AuthStore` 不读写对话内容。

## 4. API 合约

认证接口是唯一允许匿名访问的 `/api` 路由：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `POST` | `/api/auth/register` | 校验邀请口令和用户名/密码，创建用户并建立 Cookie 会话 |
| `POST` | `/api/auth/login` | 校验密码并建立 Cookie 会话 |
| `POST` | `/api/auth/logout` | 删除当前服务端登录会话并清除 Cookie |
| `GET` | `/api/auth/me` | 返回当前用户，不泄露密码或 token |

其余 `/api/sessions/**`：未登录返回 `401`；登录但不是所有者时统一返回 `404`，不暴露会话是否存在。新建会话时在同一请求内登记归属。

## 5. 前端行为

网页初始先请求 `/api/auth/me`：未登录时只显示登录/注册卡片；成功后才加载会话。Cookie 由浏览器随同源请求自动携带，前端不将 token 放进 `localStorage`。退出后清空内存中的会话视图和待上传图片。

## 6. 配置与部署

新增配置示意：

```dotenv
AUTH_ENABLED=true
REGISTRATION_INVITE_CODE=使用随机且足够长的口令
AUTH_SESSION_HOURS=168
```

`REGISTRATION_INVITE_CODE` 属于服务器机密，只写入 `~/agent/.env`（权限 `600`），不提交、截图或发送到聊天。首次发布前要备份 `data/`；升级后由第一位注册者认领旧会话，因此必须由服务器所有者先注册。

## 7. 验收与安全测试

- 未登录访问任一会话接口返回 `401`。
- 错误邀请码、弱密码、重复用户名均失败且不产生用户。
- 登录成功后响应带 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 另一用户访问、发送、删除第一个用户的会话均为 `404`，原数据不变化。
- 登出或会话过期后 Cookie 不再可用。
- 日志、接口 JSON 和 SQLite 中均不出现明文密码、原始登录 token 或邀请码。
