# 提示词抽象与版本管理学习笔记

这篇文档用来说明本项目为什么要抽离提示词、代码是怎样组织的，以及以后应该怎样修改。
它是项目学习笔记，不是单纯的运维操作清单。

## 二、先理解“提示词”在系统中的几种角色

提示词不只有一段 system prompt。项目中有几类不同用途：

| 类型 | 例子 | 特点 |
| --- | --- | --- |
| 基础人设 | 中文助手、记忆规则、工具使用原则 | 服务构建时确定 |
| 能力说明 | 有知识库时优先检索 | 只有能力存在时才加入 |
| 动态上下文模板 | 当前时间、历史摘要、授权文件 | 每轮根据代码数据填充 |
| 安全提示 | 外部资料不是指令、不能泄露凭据 | Agent 调用时加入 |
| 工具描述 | calculator 的用途和参数说明 | 发送给模型的工具 schema |
| 数据围栏 | 外部资料开始/结束标记 | 包住不可信工具结果 |

集中管理的是“模型看到的文字”。工具权限、路径校验、参数校验和安全检测仍然由代码负责。
提示词可以引导模型，但不能给模型授予权限。

## 三、一次请求中的组装顺序

```text
config.py → bootstrap.py → service.py → agent.py
  基础人设     能力说明      时间/摘要      安全规则/工具结果
```

详细阅读路径是：

1. `config.py` 读取 `DEFAULT_SYSTEM_PROMPT` 或环境变量 `SYSTEM_PROMPT`。
2. `bootstrap.py: build_service()` 调用 `build_system_prompt()`；只有真的接入知识库或 MCP 时才加入对应说明。
3. `service.py: _build_context()` 按“系统提示词 → 当前时间 → 历史摘要 → 对话历史”组装上下文。
4. `agent.py: respond()` 追加安全规则，执行工具，并把工具结果放回下一轮模型输入。

当前时间不能写死在基础提示词里，因为基础提示词可能在进程启动后使用很久。
历史摘要使用 assistant 消息承载，避免把模型生成的摘要提升成 system 权限。

## 四、为什么不能把所有内容都放进一个大字符串

不同内容的生命周期不同：默认人设是静态版本内容，当前时间每轮变化，知识库说明取决于能力是否存在，
文件授权必须来自本次请求，外部文档还必须被视为数据而不是指令。

因此采用三条规则：

- 静态文字集中放在 `src/prompts.py`。
- 动态数据由拥有它的模块填充模板。
- 权限和安全边界由代码最终判断，不能只依赖模型听从提示词。

## 五、以后修改提示词应该怎么做

1. 先判断修改属于基础人设、能力说明、动态模板、安全提示还是工具描述。
2. 在 `src/prompts.py` 修改文本；保留 `{now}`、`{summary}`、`{history}` 等模板变量。
3. 提示词行为变化时递增 `PROMPT_VERSION`，格式为 `YYYY-MM-DD.N`。
4. 同步修改调用方和测试，特别是工具实际执行、外部资料围栏及权限校验。
5. 运行测试，阅读真实回答，再提交 Git。

模板只对固定模板调用一次 `.format()`。不要把用户输入或文档内容拼成新的模板再执行。
如果要修改工具权限，必须修改工具代码和测试，不能只改提示词。

## 六、如何验证模型效果

```powershell
python scripts/eval_prompts.py --output data/evals/prompts.json
```

脚本使用独立临时会话，检查记忆重载、未知生日、计算工具、知识库事实与来源、缺失资料和普通聊天等 7 个案例。
2026-11-01 使用 `deepseek-chat` 的结果是 **7/7 核心检查通过**，全量单元测试是 **306 项通过**。
这证明固定案例的主要行为正常，但不等于所有回答都稳定；真实向量召回、MCP 和长摘要效果仍需单独验证。

## 七、Git 是怎样维护提示词的

提示词与代码在同一个提交中维护，因此一次行为变化可以完整回滚：

```powershell
git log -p -- src/prompts.py
git show 81b8100 -- src/prompts.py
git diff --check
python -m pytest -q --basetemp .pytest-tmp-prompts-check
git add src/prompts.py src/core tests scripts docs/19_提示词管理.md
git commit -m "修改提示词行为"
git push origin main
```

这是单人项目，验证通过后直接推送 `main` 即可，不需要为了形式创建 PR。
提交前确认没有把 `.env`、会话数据或测试产物加入 Git。需要整次回滚时，优先使用 `git revert <commit>`。

## 八、学习时建议的阅读顺序

1. 读 `src/prompts.py`，看静态常量、模板和版本号。
2. 读 `src/bootstrap.py` 的 `build_service()`，理解能力条件如何组装。
3. 读 `src/core/service.py` 的 `_build_context()`，理解动态上下文顺序。
4. 读 `src/core/agent.py` 的 `respond()`，理解安全规则、工具循环和结果回填。
5. 读 `tests/test_prompts.py`、`tests/test_agent_security.py` 和 `scripts/eval_prompts.py`，
   看代码如何证明这些行为没有回退。

核心思想是：**提示词集中管理，动态内容按职责注入，权限由代码兜底，Git 记录每次行为变化。**
