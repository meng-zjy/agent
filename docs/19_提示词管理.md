# 提示词管理

## 维护入口

项目自有的模型提示文本统一维护在 `src/prompts.py`，由 Git 与代码一起版本管理。
保持 Python 常量和命名模板，暂不引入模板框架或在线提示词平台。

| 内容 | 注入位置 |
| --- | --- |
| 默认基础人设 | `config.py` 提供默认值，可由 `SYSTEM_PROMPT` 整体覆盖 |
| 知识库、文件工具能力说明 | `bootstrap.py` 按实际接入的能力组装 |
| 安全提示 | `agent.py` 在已有的首条 system 消息中追加一次 |
| 当前时间 | `service.py` 每轮计算并填入模板 |
| 摘要生成、历史摘要上下文 | `service.py` 填入模板；历史摘要使用 assistant 角色 |
| 本次授权文件 | `agent.py` 从独立授权结果填入模板 |
| 外部资料围栏 | `utils.py` 包装检索及 MCP 返回内容 |
| 内置工具及参数说明 | `tools.py` 引用提示词常量构建工具 Schema |

工具名称、参数结构、权限校验和安全检测逻辑仍在各自模块中。
MCP 服务器动态提供的工具说明来自外部协议，不属于仓库中的静态提示词。
用户看到的错误、状态提示和普通工具执行结果由原业务模块维护。

模板变量只填充一次，文档、摘要等内容中的花括号不会作为模板继续执行。
提示词不会赋予权限；文件授权、禁止写操作等约束仍由工具层代码执行。

## 配置与运行定位

`SYSTEM_PROMPT` 未设置时使用默认人设；设置后整体替换默认人设，并非追加。
设置为空字符串仅关闭基础人设，其他能力说明、时间及安全规则由各自注入条件决定。
安全规则在存在 system 消息时由 Agent 追加；无 system 消息的低层 Agent 调用保持原有消息结构。

服务构建时记录以下元数据，不记录提示词正文、授权路径或会话内容：

- `prompt_version`：仓库内提示词集合的版本。
- `system_prompt_sha256`：实际组装的基础人设与能力说明的 SHA-256 指纹。
- `custom_system_prompt`：配置是否不同于默认人设。
- `has_retriever`、`has_mcp_tools`：本次构建接入的能力。

指纹不包含随后动态注入的时间、授权文件、历史摘要和 Agent 安全规则。
排查时结合版本号、Git 提交、配置及能力标记定位；自定义人设变化可由指纹区分。
构建元数据在默认 INFO 日志级别下记录，通常位于 `data/logs/agent.log`。

## 修改、验证与回滚

1. 在 `src/prompts.py` 修改文本，保留模板变量名及外部资料边界标记。
2. 提示词发生变化时更新 `PROMPT_VERSION`，采用 `YYYY-MM-DD.N`，同日递增序号。
3. 如改变条件或上下文结构，同步更新相应调用方和回归测试。
4. 运行测试并审查 Git diff。用独立提交记录提示词与配套代码，提交说明解释行为变化。
5. 合并、部署后重启服务，使导入的常量及配置生效；核对日志中的版本和指纹。

Windows 验证命令（如目录已存在，选择新的临时目录名）：

```powershell
python -m pytest -q --basetemp .pytest-tmp-prompts-check
git diff --check
git diff -- src/prompts.py src/bootstrap.py src/core tests/test_prompts.py
```

追踪历史：

```powershell
git log -p -- src/prompts.py
git show <commit>:src/prompts.py
```

回滚时优先使用 `git revert <commit>` 撤销完整提示词变更提交，保留历史并一起撤销配套调用改动。
若仅恢复旧文本，应确认模板变量和当前调用方兼容，并分配新的提示词版本、重新验证。
`SYSTEM_PROMPT` 的环境覆盖不受 Git 回滚影响，需要同时核对部署配置。
