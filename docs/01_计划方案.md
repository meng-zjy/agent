# Agent 产品开发 · 第一阶段计划方案

> 目标：从零开发一个**可上线**的 AI Agent 产品（对标豆包 / 千问）。
> 本方案为**第一步**：具备对话功能的 MVP。
> 后续能力（工具调用、MCP、RAG、多模态、并发、**记忆系统**）**均不在本期实现**，但架构需预留扩展位。

- 状态：草案 v0.2
- 更新：本期移除记忆系统；LLM 改为商汤日日新 SenseNova；确认使用 openai SDK

---

## 1. 产品定位

做一个像豆包 / 千问一样的产品级 AI Agent。采用**小步快跑、先 MVP 后演进**的方式：

1. **M1（本次）**：能对话的 MVP —— 命令行里跟大模型聊天
2. **M2（下期）**：记忆系统（会话历史 / 多轮上下文）+ Web 界面
3. **M3~M8（后续）**：工具调用、RAG、MCP、多模态、并发、上线

第一步的价值：跑通「用户输入 → 模型回复」这条主干，并把工程骨架搭对，让后面的每一步都在干净的底座上长出来。

---

## 2. 总体架构设计

> 核心思想：**分层 + 接口先行**。每一层只依赖接口，不依赖具体实现。这样后续换模型、加工具、接 RAG 都只动局部。

```
┌─────────────────────────────────────────────────┐
│              客户端层（交互）                     │
│   MVP：CLI 命令行交互                             │
│   后续：Web UI / 移动端 / 桌面端（同一服务层）    │
└───────────────────────┬─────────────────────────┘
                        ▼
┌─────────────────────────────────────────────────┐
│            Agent 核心（执行循环）                 │
│   MVP：直答模式（消息 → 模型 → 回复）            │
│   后续：ReAct 循环 / 工具调用 / MCP 编排         │
└───────────────────────┬─────────────────────────┘
                        ▼
┌─────────────────────────────────────────────────┐
│          Provider 抽象层（LLM 适配）             │
│   BaseProvider（统一接口）                       │
│   └── SenseNovaProvider（本期，OpenAI 协议）     │
│   └── (预留) Qwen / Doubao / DeepSeek / 多路并发 │
└─────────────────────────────────────────────────┘
        │
        ▼   （下一期 M2 加入）
┌─────────────────────────────────────────────────┐
│           记忆层 Memory（M2 实现）               │
│   · 会话历史 / 多轮上下文                        │
│   后续：长期记忆 / 向量检索（RAG）               │
└─────────────────────────────────────────────────┘
```

**为未来预留的扩展点（本期不做，但架构已留位）：**

| 未来能力 | 预留位置 | 说明 |
|---|---|---|
| 记忆系统 / 多轮上下文 | 记忆层（**M2 实现**） | 本期 Agent 每次独立请求；M2 在此层做会话历史 |
| 工具调用 / ReAct | Agent 核心层 | MVP 是直答实现，后续同一接口替换为「循环执行」 |
| MCP | Agent 核心层 + Provider 层 | MCP 作为工具的标准化来源接入执行循环 |
| RAG | 记忆层（M2 之后） | 在记忆层基础上接向量库实现 |
| 多模态 | 消息模型 + Provider 层 | 统一消息模型预留 `content` 的多样式扩展 |
| 多路 / 并发 | Provider 层 + 服务层 | 接口天然可挂多个 provider / 多 worker |
| Web 化 | 服务层之上 | M2 引入服务层后，在其上包一层 FastAPI |

## 4. 技术选型与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11+ | 与现有项目一致，AI 生态最全 |
| LLM SDK | `openai` SDK（直接使用） | **已确认**，见下方说明 |
| 模型 | 商汤日日新 `sensenova-6.8-flash-lite` | 用户指定，OpenAI 协议兼容 |
| API 地址 | `https://token.sensenova.cn/v1` | 商汤官方入口 |
| 配置 | `pydantic-settings` + `.env` | 沿用 clbot-agent 的习惯 |
| 测试 | `pytest` | 标准选择 |

### 关键决策（已确认）：直接用 `openai` SDK，不引入 LangChain

理由：

1. **可控性**：MVP 只需要「消息 → 模型 → 回复」，用 LangChain 会引入大量用不到的抽象，排查问题更难
2. **为后续铺路**：工具调用、ReAct、MCP 这些后续能力，自己基于 OpenAI 原生接口写执行循环反而更清晰、更好调试；LangGraph 版本迭代快、锁定风险高
3. **生产可维护**：生产级 agent 的主流做法是「薄封装 + 原生 SDK」，依赖越少越好升级

> ✅ 已由用户确认。参考：现有 clbot-agent 使用 LangChain，可作对照；若后续 M7 多 Agent 阶段需要图编排再评估。

### API Key 安全约定

- 用户提供的 API Key 只写入项目根目录 `.env` 文件
- `.env` 加入 `.gitignore`，**不进入版本库、不硬编码进代码、不写入本方案文档**
- `.env.example` 只保留占位符 `sk-xxx`，供其他人参考格式

## 6. 核心模块设计

### 6.1 统一消息模型 `core/models.py`

采用 OpenAI 消息格式作为内部统一模型，为工具调用 / 多模态留字段：

```python
class Role(str, Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"

@dataclass
class Message:
    role: Role
    content: str
    # 预留：后续工具调用加 tool_calls / tool_call_id
    # 预留：多模态时 content 支持结构化(文本+图片URL)列表

@dataclass
class Conversation:
    messages: list[Message]  # M2 记忆系统引入后用于承载多轮上下文
```

### 6.2 Provider 抽象 `core/provider.py`

统一接口，任何 LLM 只要实现它就能接入：

```python
class BaseProvider(ABC):
    @abstractmethod
    def chat(self, messages: list[Message]) -> str: ...
    @abstractmethod
    def chat_stream(self, messages: list[Message]) -> Iterator[str]: ...
```

`providers/sensenova.py` 基于 `openai` SDK 实现：

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://token.sensenova.cn/v1",
    api_key=settings.sensenova_api_key,
)
resp = client.chat.completions.create(
    model="sensenova-6.8-flash-lite",
    messages=[{"role": "user", "content": "Hello!"}],
    stream=True,   # 流式
)
```

### 6.3 Agent 核心 `core/agent.py`

MVP 阶段就是最简单的「直答」——单条消息交给模型，返回流式回复：

```python
class ChatAgent:
    def __init__(self, provider: BaseProvider): ...

    def respond(self, message: str) -> Iterator[str]:
        # MVP: 直答（单次输入→流式回复），无记忆
        # M2: 传入 Conversation，带会话历史；后续再演进为工具循环
        messages = [Message(role=Role.USER, content=message)]
        yield from self._provider.chat_stream(messages)
```

### 6.4 CLI 入口 `cli.py`

- 启动时显示欢迎语 + 模型信息（`sensenova-6.8-flash-lite`）
- 循环读取用户输入：
  - `/exit` → 退出
  - `/help` → 显示可用命令
  - 其他 → 调 `ChatAgent.respond()`，流式打印回复
- 网络 / 鉴权异常时打印友好提示，程序不退出

## 10. 风险与注意事项

1. **API 成本**：流式会累积 token，README 里写清楚成本意识；配置中预留 max_tokens 限制
2. **API Key 安全**：只存 `.env`，gitignore 必须生效，绝不提交 / 不硬编码
3. **接口变动**：`openai` SDK 升级可能破坏兼容，requirements.txt 锁定版本
4. **提示注入**：本期是本地 CLI 不涉及，但对外服务化（M2/M8）时要加防护，先记住
5. **上下文窗口**：本期无记忆不影响；M2 引入多轮上下文后，要设计历史截断策略，避免超限
