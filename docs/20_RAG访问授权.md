# RAG 访问授权

## 1. 目标与范围

在已有邀请码账户和会话隔离基础上，按知识库控制读权限。管理员创建知识库、维护文档并分配权限；普通用户只能预览和检索公开库或获授权库。

首版使用已有 SQLite 和内存向量检索，不引入向量数据库、组织架构或单段落权限。

## 2. 身份、角色与权限

- 身份从后端验证过的登录 Cookie 取得，沿 `API → ChatService → ToolExecutionContext → ToolRegistry` 显式传递用户 ID。
- 第一位账户是管理员。升级已有数据库时，最早注册的账户自动取得管理员资格；新注册账户不会自动成为管理员。升级前须确认最早账户属于服务器所有者。
- 管理员能管理和读取所有知识库，但仍不能读取其他用户的聊天会话。
- 公开库允许所有已登录用户读取；受限库只允许管理员和显式授权用户读取。
- 工具 Schema 只允许 `query`，不允许模型提交 `user_id`、权限或任意文档路径。缺失后端身份时，受限检索拒绝执行。

## 3. 提示词与程序各负责什么

| 行为 | 实现位置 | 保证程度 |
| --- | --- | --- |
| 登录身份、管理员判定 | `AuthStore` | 后端硬约束 |
| 公开库和授权范围 | `KnowledgeCatalog` | 后端硬约束 |
| 检索候选集 | `AuthorizedRetriever` | 先选有权限的索引，再搜索与排名 |
| 预览、更新、删除、授权接口 | API 与存储层 | 服务端重新校验，不依赖按钮可见性 |
| 优先检索、标注来源、没有依据时说明资料不足 | `prompts.py` | 提示词软约束，不保证每次遵从 |
| 不执行资料中的指令 | 资料围栏、现有检测及提示词 | 辅助防线，不代替访问授权 |

模型不会收到未经授权的检索片段。模型自带知识、猜测或用户自己贴入的信息，不属于本系统可以凭知识库权限阻止的范围。

## 4. 存储与迁移

账户数据库保留原表，新增 `administrators(user_id)`。知识数据库默认 `data/knowledge.db`：

| 表 | 主要字段 | 规则 |
| --- | --- | --- |
| `knowledge_bases` | `id`, `name`, `public`, `revision`, `created_by`, `created_at`, `updated_at` | UUID 标识；默认受限；正文更新时增加版本 |
| `knowledge_documents` | `id`, `knowledge_base_id`, `name`, `content`, `created_by`, `created_at`, `updated_at` | 库内名称唯一；同名保存覆盖正文，文档 ID 保持不变 |
| `knowledge_grants` | `knowledge_base_id`, `user_id`, `granted_by`, `created_at` | 库与用户联合主键；重复授权、撤权均可安全重试 |
| `knowledge_audit` | `actor_id`, `action`, `target_id`, `created_at` | 写操作与审计同事务提交；不存正文、密码或登录凭据 |

知识库数据由 `KnowledgeCatalog` 管理，账户数据由 `AuthStore` 管理；管理员判定调用其公开方法，不跨模块直接查询账户表。

账户模式首次启动会将原 `KNOWLEDGE_DIR` 的 `.md/.txt` 导入 `legacy` 受限库，保留原文件。此导入是一次性快照，重启不会重复导入、覆盖管理页面的修改，也不会将旧文件自动公开。导入失败会回滚事务并停止启动，修复文件后可重试。后续应通过管理页面维护数据库内的文档。

## 5. 核心流程

1. 管理员登录，点击聊天页的“知识库”。
2. 创建知识库，默认受限；可在创建时明确选择所有登录用户可读。
3. 输入 `.md/.txt` 文件名并粘贴正文，保存到所选库。同名保存用于更新。
4. 给指定普通用户授予访问。用户刷新知识库列表即可看到资料。
5. 用户提问；模型调用检索工具时，后端重新读取权限，只对已授权库建立和查询索引。
6. 多库结果按分数合并为 top-k；片段附带库名、文档名、库 ID、文档 ID 和块编号。标注引用由模型组织，用户可在知识库页面预览原文核对。

## 6. API

| 方法 | 路径 | 权限与行为 |
| --- | --- | --- |
| GET | `/api/auth/me` | 原响应的 `user` 新增 `is_admin` |
| GET | `/api/admin/users` | 管理员列出 ID、用户名、管理员标识，不含凭据 |
| GET | `/api/knowledge-bases` | 仅返回当前用户可访问的库 |
| POST | `/api/knowledge-bases` | 管理员创建，正文 `{name, public}` |
| GET | `/api/knowledge-bases/{id}/documents` | 有权用户列出该库文档 |
| GET | `/api/knowledge-bases/{id}/documents/{doc}` | 有权用户预览正文 |
| PUT | `/api/knowledge-bases/{id}/documents` | 管理员保存，正文 `{name, content}` |
| DELETE | `/api/knowledge-bases/{id}/documents/{doc}` | 管理员删除 |
| GET | `/api/knowledge-bases/{id}/grants` | 管理员查看授权用户 ID |
| PUT | `/api/knowledge-bases/{id}/grants/{user}` | 管理员授权，目标用户须存在 |
| DELETE | `/api/knowledge-bases/{id}/grants/{user}` | 管理员撤权 |

未登录返回 401；管理操作权限不足返回 403；普通用户请求无权或不存在的知识库、文档统一返回 404。文档名只作为标签，不作为磁盘路径；新建文档须为 `.txt/.md`，最多 120 字，正文最多 200000 字，库名最多 80 字。

## 7. 索引、撤权与并发

每个库独立内存索引，文档变更增加库版本，下一次检索按版本重建；无用户检索结果缓存。权限在每次工具调用时重新查询，不以登录时的权限快照作为依据。

首版用进程内锁串行化知识库写操作与检索。撤权提交后开始的检索不再读取该库；提交前已经取得的资料或已经发出的模型请求无法撤回。单进程、小规模使用时容易验证，规模扩大后再优化锁与索引构建。不要运行多个 worker 或多个进程共享同一数据目录。

**撤权不会删除或清洗旧聊天、摘要和用户已保存的资料。** 历史回答可能继续进入模型上下文。若业务要求撤权后历史信息也不可使用，应进一步实现来源追踪、历史上下文失效及受影响会话清理；当前版本不作该承诺。

公开库的个人授权撤销不改变其公开属性；当前页面不提供公开/受限切换，创建时应确认范围。此版本不支持更换管理员、文档级 ACL、文件上传、自动引用链接、审计查询页面或管理员代读用户会话。

## 8. 部署与使用

```dotenv
ACCOUNT_ENABLED=true
KNOWLEDGE_DATABASE=/app/data/knowledge.db
```

本机直接运行时可保留默认相对路径 `data/knowledge.db`。数据库及原有账户、会话均在 `data/` 持久化；备份时应先停止应用，完整备份该目录，保持数据库与会话一致。

账户模式的 CLI 没有登录身份，因此不加载全目录 RAG；不能通过 CLI 绕过新知识库授权。账户关闭时保留原单人目录检索模式，不读取新知识数据库。

嵌入模型必须可用，真实检索才会启用；加载失败仍按原逻辑降级为聊天，管理页面的资料预览和授权不受影响。`/health` 的 `ok` 不代表 RAG 模型可用，新增的 `rag.state` 分别报告 `ready`、`disabled` 和 `unavailable`。聊天与管理页面显示相应提示；仍应结合真实问题验证工具调用。持久化缓存和离线加载操作见部署文档第 11 节。

## 9. 验收与验证

`tests/test_knowledge.py` 使用假模型覆盖：管理员初始化与旧账户迁移、公共/受限库、检索前权限过滤、重复授权/撤权、匿名身份拒绝、模型伪造用户 ID、共享工具并发隔离、文档更新和删除使索引失效、原文预览拒绝越权、一次性旧资料导入、授权与审计重启持久化，以及通过聊天 SSE 的真实工具执行链验证模型只收到有权限的检索结果。

浏览器人工验收：管理员创建两份不同资料并分别授权两位用户，用两个独立浏览器会话检查列表、预览和聊天；撤权后重新检索及刷新预览应失去访问；容器重启后授权与文档应保留。单元测试不覆盖真实嵌入模型下载和浏览器交互。
